Push notifications get a few words on a lock screen, and too many irrelevant ones make people turn them off for good. Good push copy is specific, timely and useful to the reader. This push notification copy prompt writes short titles and messages for each moment in the user journey, with timing rules and test ideas so you send fewer, better notifications.

## Prompt

```prompt
Act as a mobile lifecycle marketer. Write push notification copy for my app.

App and what it does: [APP]
Audience: [USERS]
Moments to cover (e.g. onboarding day 1, abandoned action, streak at risk, new feature, offer, win-back): [MOMENTS]
Brand voice: [VOICE]
Offer or promotion, if any: [OFFER OR "NONE"]
Personalization data available (name, last action, location): [DATA]

For each moment deliver:
1. 3 variants with a title (max 40 characters) and body (max 90 characters), using {FIRST NAME} or other tokens only where data exists.
2. The deep link destination (which screen it should open).
3. Best send timing and frequency cap.
4. The trigger or segment rule.
Then:
5. Rules to avoid notification fatigue (quiet hours, max per week, when to stop).
6. Two A/B tests to run first and the metric to judge them (open rate, action completed, opt-outs).
No clickbait, no false urgency.
```

## How to use it

1. **Start with behavior-triggered moments**; they usually beat broadcast blasts.
2. **Check how copy truncates** on both iOS and Android lock screens.
3. **Watch opt-out rates** as closely as open rates.
